# 🚀 Edlide Backend - План реализации единой экосистемы

у нас для бэкэнде mcp supabse + Droplet Infrastructure

## 📋 **Цель проекта**

Создать единую backend систему для Edlide, которая объединяет:
- Сайт для покупки подписок (3 тарифа)
- Единую авторизацию для сайта и IDE
- Админскую панель для управления пользователями, Droplet серверами и API ключами
- Гибкую масштабируемую инфраструктуру с Droplet прокси-серверами

---

## 🎯 **Ключевые требования**

### **1. Единая система авторизации**
- Один UUID пользователя работает и на сайте, и в IDE
- JWT токены для безопасной авторизации
- Отслеживание устройств (Web vs IDE)

### **2. Сайт edlide.com**
- Landing страница с описанием продукта
- Страница тарифов с 3 планами подписок
- Личный кабинет со статистикой использования и входом в аккаунт
- Страница профиля для управления аккаунтом
- Система регистрации и входа

### **3. Тарифные планы**
- Starter: $6 в месяц (100 запросов в день)
- Pro: $20 в месяц (2000 запросов в день)
- Enterprise: $40 в месяц (5000 запросов в день)

### **4. Интеграция с IDE**
- Авторизация через сайт (Google или email)
- Лимиты отображаются только на сайте в реальном времени
- Прокси запросов через Droplet серверы с контролем использования
- Базовая информация о лимитах, полная статистика только на сайте
- Автоматическая маршрутизация через привязанный Droplet

### **5. Droplet Infrastructure**
- Автоматическое создание Droplet серверов через DigitalOcean API
- Гибкое распределение пользователей по Droplet (1:1, 1:N, N:M)
- Простые прокси-серверы без дополнительной логики
- Мониторинг здоровья и отказоустойчивость
- Управление Chutes API ключами для каждого Droplet

### **6. Админская панель**
- Управление всеми пользователями
- Создание и управление Droplet серверами
- Гибкое распределение пользователей по Droplet серверам
- Мониторинг нагрузки и статуса Droplets
- Управление подписками и API ключами Chutes
- Система уведомлений о сбоях серверов

## 🏗️ **Архитектура системы**

### **Backend инфраструктура**
- Supabase как основной хаб и база данных
- Droplet серверы как прокси-инфраструктура
- Edge Functions для API эндпоинтов
- JWT middleware для авторизации
- Dodo Payments для обработки платежей
- DigitalOcean API для управления Droplet серверами

### **Основные компоненты**
- Users: Единая база пользователей
- Droplets: Управление прокси-серверами и их статусами
- UserDropletMappings: Гибкие связи пользователей с Droplets
- ChutesAccounts: API ключи Chutes для каждого Droplet
- Subscriptions: История платежей и тарифы
- UsageLogs: Статистика использования через Supabase
- UserSessions: JWT токены и сессии

### **API эндпоинты**
- Auth: регистрация, вход, проверка токена, выход
- User: статистика, статус, профиль
- Droplets: управление Droplet серверами (создание, мониторинг, удаление)
- Chat: маршрутизация запросов через Droplet → Chutes
- Payments: обработка платежей и webhook
- Admin: управление пользователями, Droplets и мониторинг
- HealthCheck: проверка статуса Droplet серверов

## 📊 **База данных**

### **Таблица пользователей**
- UUID, email, пароль, имя, фамилия
- Даты создания и последнего входа
- Статус подписки и привязанные Droplets

### **Таблица Droplets**
- Уникальный ID, IP адрес, статус
- Информация о нагрузке и доступности
- Chutes API ключ для этого Droplet
- Дата создания и последней проверки

### **Таблица UserDropletMappings**
- Гибкие связи пользователей с Droplets
- Тип связи (1:1, 1:N, N:M на уровне логики)
- Даты привязки и активации
- Приоритет Droplet для пользователя

### **Таблица ChutesAccounts**
- API ключи для разных Droplets
- Статус ключа и лимиты
- История использования
- Привязка к конкретному Droplet

### **Подписки и платежи**
- История всех платежей
- Статус платежа (ожидание, завершен, ошибка)
- Сумма и дата платежа
- ID платежа в системе

### **Логи использования**
- Запросы с детализацией по моделям
- Маршрут: ID пользователя → ID Droplet
- Устройства (IDE или браузер)
- Токены и количество запросов
- Временные метки

### **Сессии пользователей**
- JWT токены
- Информация об устройствах
- IP адреса и user agent
- Срок действия токенов
- Информация о привязанном Droplet

## 🚀 **План реализации**

### **Этап 1: Фундамент и база данных (3-4 дня)**
Настройка Supabase, создание таблиц для Droplet инфраструктуры, базовая структура проекта

### **Этап 2: Авторизация и маршрутизация (4-5 дней)**
Единая регистрация и вход, JWT токены, middleware, определение Droplet для пользователя

### **Этап 3: Сайт (5-6 дней)**
Next.js приложение, основные страницы, UI компоненты с учетом Droplet архитектуры

### **Этап 4: Droplet Infrastructure (4-5 дней)**
Интеграция DigitalOcean API, создание Droplet серверов, система прокси

### **Этап 5: Core API с маршрутизацией (4-5 дней)**
Маршрутизация запросов через Droplet, система лимитов, статистика в Supabase

### **Этап 6: Платежи (3-4 дня)**
Интеграция Dodo Payments, webhook, управление подписками, автоматическое выделение Droplet

### **Этап 7: IDE интеграция с прокси (3-4 дня)**
Авторизация в IDE, UI для входа, отображение лимитов, работа через Droplet

### **Этап 8: Админская панель (3-4 дня)**
Управление Droplet серверами, распределение пользователей, мониторинг здоровья

### **Этап 9: Система уведомлений и отказостойкость (2-3 дня)**
Email уведомления о сбоях, health check система, обработка ошибок

### **Этап 10: Тестирование и деплой (3-4 дня)**
Тестирование всех компонентов, нагрузочное тестирование, деплой на продакшн

**Итого: 31-39 дней (~6-8 недель)**
