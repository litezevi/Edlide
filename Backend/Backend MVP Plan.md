# 🚀 Edlide Backend - План реализации единой экосистемы

## 📋 **Цель проекта**

Создать единую backend систему для Edlide, которая объединяет:
- Сайт для покупки подписок (3 тарифа)
- Единую авторизацию для сайта и IDE
- Админскую панель для управления пользователями и API ключами

---

## 🎯 **Ключевые требования**

### **1. Единая система авторизации**
- Один UUID пользователя работает и на сайте, и в IDE
- JWT токены для безопасной авторизации
- Отслеживание устройств (Web vs IDE)

### **2. Сайт edlide.com**
- Landing страница с описанием продукта
- Страница тарифов с 3 планами подписок
- Личный кабинет со статистикой использования и входом в аккаунт
- Страница профиля для управления аккаунтом
- Система регистрации и входа

### **3. Тарифные планы**
- Starter: $6 в месяц (100 запросов в день)
- Pro: $20 в месяц (2000 запросов в день)
- Enterprise: $50 в месяц (5000 запросов в день)

### **4. Интеграция с IDE**
- Авторизация через сайт (Google или email)
- Лимиты отображаются только на сайте в реальном времени
- Прокси к Chutes API с контролем использования
- Базовая информация о лимитах, полная статистика только на сайте

### **5. Админская панель**
- Управление всеми пользователями
- Создание и управление API ключами
- Привязка API ключей к конкретным пользователям
- Просмотр статистики и логов использования
- Управление подписками

---

## 🏗️ **Архитектура системы**

### **Backend инфраструктура**
- Supabase как основная база данных
- Edge Functions для API эндпоинтов
- JWT middleware для авторизации
- Dodo Payments для обработки платежей

### **Основные компоненты**
- Users: Единая база пользователей
- Chutes Accounts: Привязка к AI провайдеру
- Subscriptions: История платежей и тарифы
- Usage Logs: Статистика использования
- User Sessions: JWT токены и сессии

### **API эндпоинты**
- Auth: регистрация, вход, проверка токена, выход
- User: статистика, статус, профиль
- Chat: прокси к Chutes с контролем лимитов
- Payments: обработка платежей и webhook
- Admin: управление пользователями и ключами

---

## 📊 **База данных**

### **Таблица пользователей**
- UUID, email, пароль, имя, фамилия
- Даты создания и последнего входа

### **Тарифные аккаунты**
- Привязка к пользователю
- API ключ Chutes
- Текущий тариф и статус
- Дневные лимиты и использование
- Дата последнего сброса счетчика

### **Подписки и платежи**
- История всех платежей
- Статус платежа (ожидание, завершен, ошибка)
- Сумма и дата платежа
- ID платежа в системе

### **Логи использования**
- Запросы с детализацией по моделям
- Устройства (IDE или браузер)
- Токены и количество запросов
- Временные метки

### **Сессии пользователей**
- JWT токены
- Информация об устройствах
- IP адреса и user agent
- Срок действия токенов

## 🔐 **Процесс авторизации**

### **Регистрация**
- Пользователь регистрируется на сайте
- Создается запись в базе данных
- Выдается JWT токен
- Доступ к сайту и IDE

### **Вход**
- Единая форма входа для сайта и IDE
- Проверка учетных данных
- Возврат JWT токена и информации о подписке
- Отслеживание устройства входа

### **Проверка токена**
- IDE использует JWT для авторизации запросов
- Валидация токена на каждом запросе
- Возврат информации о пользователе и лимитах
- Автоматическое обновление при необходимости

## 🚀 **План реализации**

### **Этап 1: Фундамент (3-4 дня)**
Настройка Supabase, создание таблиц, базовая структура проекта

### **Этап 2: Авторизация (4-5 дней)**
Единая регистрация и вход, JWT токены, middleware

### **Этап 3: Сайт (5-6 дней)**
Next.js приложение, основные страницы, UI компоненты

### **Этап 4: Core API (4-5 дней)**
Прокси к Chutes, система лимитов, статистика

### **Этап 5: Платежи (3-4 дня)**
Интеграция Dodo Payments, webhook, управление подписками

### **Этап 6: IDE интеграция (3-4 дня)**
Авторизация в IDE, UI для входа, отображение лимитов

### **Этап 7: Админка (2-3 дня)**
Панель управления, мониторинг, инструменты поддержки

### **Этап 8: Тестирование и деплой (2-3 дня)**
Тестирование всех компонентов, деплой на продакшн

**Итого: 26-34 дня (~5-7 недель)**
